DeepSeek Harness 这周发了 **v0.1.0-rc.8**，这是 beta 之后的第一次大更新：14 项改动，多模态输入是头条。但比任何一个单独功能更值得说的，是节奏本身——Harness 已经稳定在**大约一周三更**的频率上，这改变了「用 DSH」这件事的含义。

## rc.8 到底有什么

头条是**原生图片输入**：agent 现在可以直接接收「文字 + 图片」混合的提示，图片不再是二等公民、不再需要外挂通道。听起来小，其实不小。一旦 agent 能「看」，一整类工作就被打开了——读一张截图然后行动、解析一张图表、检查渲染后的页面而不是对着标记猜。

其余 13 项改动里，包括子代理升级（Codex 和 Claude Code 后端），以及常规的修复长尾。列表本身不如「形状」重要：多模态不再是「规划中」，而是已经在发货。

## 为什么节奏比 changelog 更重要

一个每周都在发的年轻运行时，同时说明了两件事：

- **势头是真的。** 周更意味着贡献者社区真的在动，而不是发布冲高之后归于沉寂的仓库。
- **插件作者追的是移动靶。** 每次更新都可能改一个契约——我们之前写过 rc.7 把 `settings.plugin.item` 槽位改成 keyed，就是这个模式：接口层演进很快，「昨天还能跑」不是部署策略。

对维护者来说，教训是：读 release notes 要像读依赖的 breaking-changes 日志那样——在插件挂掉之前读，而不是之后。

## 多模态是被低估的解锁点

纯文本的 agent 卡在「看不见」上，只能靠描述。图片输入把这个闭环补上了：截图 → 诊断 → 修复，图表 → 理解 → 实现，收据/发票 → 结构化数据。这类能力会悄悄地把 agent 从「副驾驶」推到「操作员」。

## 结论

rc.8 不是一个里程碑版本，它是一个证据：这个项目已经不再是「那个刚发布的玩意儿」，而是「那个一直在发货的东西」。如果你在 DSH 上做开发，要按「高速迭代」来规划——把插件钉在具体版本上、读更新日志、把 changelog 当成 CI 的一部分，而不是事后补课。
