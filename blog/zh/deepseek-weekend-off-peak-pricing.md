DeepSeek 又把峰谷计费规则调了一次——这次对开发者来说是实打实的利好。自 **北京时间 2026 年 8 月 23 日 00:00** 起，周末不再区分峰谷时段：**周六、周日全天统一按低谷价计费**。

## 先快速回顾一下现行规则

DeepSeek 的 V4 API 从 8 月中旬起实行错峰计价：

- **高峰**（工作日）：北京时间 09:00–12:00、14:00–18:00。
- **低谷**：其余时段——价格是高峰的**一半**。

这个拆分一直是盯着 token 账单的人手里最大的杠杆。现在，周末被整个并进了便宜的那一侧。

## 到底改了什么

代码一行都不用改，纯粹是「表」变了：

- **工作日**：保留峰谷拆分，高峰窗口仍是 09:00–12:00、14:00–18:00。
- **周末**（周六 + 周日）：全天按低谷价计费。

也就是说，周日午后跑的一个批量任务——以前若落在高峰窗口就按峰价算——现在直接半价，不用再做调度上的体操。

## 实操上意味着什么

- **把能等的工作挪到周末。** 批量任务、回填、评测、微调、数据处理——凡是能等到周末的，都该等到周末。
- **工作日不变。** 9–12 / 14–18 的高峰窗口依然翻倍，工作日的工作量还是要绕着这两个窗口排。
- **兴趣项目和副业更便宜了。** 周末折腾是最常见的使用方式，现在它全天都是低谷价。

## 更大的图景

这是两周内的第二次定价动作——先有峰谷拆分，现在又划出周末。套路是一致的：DeepSeek 在用价格削峰填谷，把用量往算力空闲的时段引。上次的头条是「低谷半价」，这次是「周末永远是低谷价」。

对直接在 API 或 DSH 上开发的人来说，实操规则一句话就够了：**工作日，躲开两个高峰窗口；周末，不用想。**

## 结论

更便宜的周末，是个小改动，但对个人开发者和中小团队影响不小——这群人最可能在自己时间里跑重活。如果你之前一直在为周末的实验精打细算，现在不用了。
